This page explains which data Deepslate stores when you use the platform, how you control it, and how **Zero Data Retention (ZDR)** works for sessions on the Realtime API.

## Overview

By default, Deepslate stores call data so you can review and analyze your calls in the Deepslate platform, for example to check transcripts, debug a conversation, or improve your system prompt.

| Data | Stored by default | Stored with ZDR |
|------|:-----------------:|:---------------:|
| Session metadata (start and end time, duration, model) | <Icon icon="check" /> | <Icon icon="check" /> |
| Usage records (feature types, unit counts) | <Icon icon="check" /> | <Icon icon="check" /> |
| Technical telemetry (latency, generation time, VAD events, turn IDs, tool call IDs) | <Icon icon="check" /> | <Icon icon="check" /> |
| Transcripts and chat history | <Icon icon="check" /> | <Icon icon="xmark" /> |
| Tool calls (tool names, arguments, results) | <Icon icon="check" /> | <Icon icon="xmark" /> |
| System prompts | <Icon icon="check" /> | <Icon icon="xmark" /> |
| Audio recordings | <Icon icon="check" /> (can be turned off) | <Icon icon="xmark" /> |
| Client IP address | <Icon icon="check" /> | <Icon icon="xmark" /> |
| System prompts flagged by automated abuse screening¹ | <Icon icon="check" /> | <Icon icon="check" /> |

¹ System prompts are screened automatically for violations of our usage policies. A flagged prompt is kept until it has been reviewed. If the flag turns out to be wrong, the prompt is deleted. If a violation is confirmed, the prompt is retained.

<Info>
**Your data is not used for model training without your consent.** Deepslate does not train its models on your call data unless you have explicitly agreed to it.
</Info>

### Retention periods and deletion

To have stored call data deleted, contact us at [support@deepslate.eu](mailto:support@deepslate.eu). When your contract ends, your data is deleted in accordance with your Data Processing Agreement (DPA).

## Zero Data Retention

Zero Data Retention is designed for workloads with especially sensitive data, for example in insurance, banking, or healthcare. With ZDR enabled, audio, transcripts, chat history, system prompts, and tool call content are processed exclusively in volatile memory, only for as long as needed to run the session in real time, and are **never persisted** by Deepslate.

<Note>
Zero Data Retention is an **Enterprise feature** and applies to the **Realtime API only**.
</Note>

### Availability

| | Covered by ZDR |
|---|---|
| Realtime API (WebSocket) | Yes |
| SDKs and plugins (LiveKit, Pipecat) | Yes, as they connect through the Realtime API |
| Assistants and Agents (inbound and outbound phone calls via the platform) | No |

### What is still stored

To operate and bill the service, Deepslate keeps the data marked as stored with ZDR in the [overview](#overview). This data contains no audio, transcripts, or chat history. It is limited to technical values such as timestamps, durations (including audio duration), generation times, and IDs, plus system prompts flagged by abuse screening as described above.

### Limitations

<AccordionGroup>
  <Accordion title="Limited support and debugging" icon="life-ring">
    Because Deepslate does not have the conversation content of ZDR sessions, we cannot inspect them when you report an issue. Troubleshooting is limited to the technical telemetry listed above. To help us debug, include the session ID and a description of what happened.
  </Accordion>

  <Accordion title="No call review in the platform" icon="eye-slash">
    ZDR sessions do not show transcripts, chat history, or recordings in the Deepslate platform. Tool calls appear with a generic label instead of the tool name.
  </Accordion>

  <Accordion title="Keeping your own records" icon="floppy-disk">
    If you need a record of the conversation, store it on your side. Your client can request the full conversation at any time during the session with [`ExportChatHistoryRequest`](/api-reference/realtime). The SDKs and plugins expose the same capability as chat history export.
  </Accordion>
</AccordionGroup>
